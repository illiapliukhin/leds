# LED_Simulator.exe — симулятор системы mono_split (Windows)

Один файл `LED_Simulator.exe` (~30 МБ), установка и Python не нужны.

Сборка: (1) GitHub Actions на windows-latest — workflow лежит в `tools/led_sim_windows/ci/led_sim_windows.yml`;
чтобы он заработал, перенесите его в `.github/workflows/` (для push нужен токен со scope `workflow`:
`gh auth refresh -s workflow`). (2) Кросс-сборка на Linux через Wine (так собран текущий exe):
`x86_64-w64-mingw32-gcc` → `build/led_host.dll`, затем Windows-Python 3.12 (nuget-пакет) под Wine:
`pip install pygame==2.6.1 numpy==1.26.4 pyinstaller` и
`python -m PyInstaller --onefile --windowed --name LED_Simulator --add-data "data;data" --add-binary "build/led_host.dll;." run_sim.py`.
Проверка exe: `LED_Simulator.exe --shots DIR` снимает скриншоты всех вкладок (папка `screenshots/` — снято так под Wine).

## Как устроено (переиспользование прошивки)

* **Настоящий код прошивки, а не порт.** `host/led_host.c` подключает *без изменений*
  `firmware/mono_split/main/demo.c`, `stack.c`, `patterns.c` и собирается MinGW-gcc в `led_host.dll`
  (на Linux — `build/libledhost.so`). FreeRTOS/ESP-IDF заменены заглушками (`host/stubs/`), железо — маленьким sim-HAL.
  Python вызывает через ctypes:
  * `render()` из demo.c — все одиночные демо (smiley, logo, scroll «ILLIA», ball, life, ring, plasma, tilt, vyshyvanka, aurora, kinetic);
  * `render_tile()/canvas_px()` из stack.c — общий холст стека (scroll, ball, plasma, wipe, vyshyvanka, aurora, kinetic, цикл);
  * `compute_grid()` из stack.c — раскладка плиток по рёбрам PRES; `crc8()` кадров RS-485;
  * гамма-таблица `build_gamma()` и BCM-слоты яркости `((2<<k)*br+127)/255` из matrix_refresh.c (8 бит, гамма 2.2) — бит-в-бит.
* **Конечный автомат стека** (`ledsim/stack_model.py`) — построчный перенос `stack_task()/discover()/probe_side()/handle_common()`:
  выборы (наименьший ID), HELLO/LEADER/TOKEN/PRESHI/SEEN/TOKDONE/MAP/TIME/PING/PONG, повторное обнаружение,
  слияние/разделение. У каждой платы свой экземпляр (свой ID и состояние). Все платы шагаются пакетно по 1 мс без потоков;
  ждущая плата пропускается до своего таймаута или прихода кадра, поэтому 100+ плат идут в реальном времени.
* **Провода** выводятся из раскладки: RS-485 — общая шина на группу соединённых кабелем плат, PRES — по конкретному порту,
  FRAME_SYNC — общий фронт группы (кадр, скос фронта в мкс, Δкадр к лидеру).
* **Тип A FFC** и обрыв столбца берутся из модели netmodel/cable (`sim/bringup`), посчитанной по настоящим .kicad_pcb
  (`data/cable_*.json`, `data/ffc_*.json`). Геометрия плат/панелей для инспектора — `tools/export_pcb.py` (.kicad_pcb → JSON).

## Вкладки

**Система** — холст: `+ Плата`, `+ Панель` (тип full / flat / lattice — кнопка справа), перетаскивание с привязкой к сетке 10 мм,
`R` — поворот, `Del` — удалить. Кабель: тянуть от порта N/E/S/W одной платы к порту другой (или «Авто-кабели» для соседей).
FFC: тянуть от квадратика на панели к плате (или «FFC к ближайшей плате», «Авто-панели»). Клик по кабелю — отключить/подключить.
Видно в реальном времени: выборы, обнаружение (жёлтые порты = PRES в момент опроса, жёлтые линии = найденные рёбра),
роль/ID/позиция/fps/скос каждой платы, размер холста групп. Анимация — для группы выбранной платы или для всех групп.
Яркость, гамма, fps стека, скорость симуляции, пауза (Пробел). Пресеты 1×1, 3×2, 6×1, 2×2, 10×10. Сохранить/Загрузить — JSON.

Неисправности: выбрать панель → «FFC: Тип A (зеркальный)», «Обрыв столбца ±»; выбрать кабель → «Кабель тип A»
(зеркальный JST-SH: GND↔PRES, RS485_A↔FRAME_SYNC — связь разрывается, стек делится на две группы); выбрать плату → «Обесточить».

`MAXB 16` — предел прошивки (16 плат в стеке, 64 ребра). `MAXB 256` — расширенный режим для больших сборок (пресет 10×10 включает его сам).
`Тайминги`: `hw` (как в прошивке на железе), `sim` (ветка MONO_SIM, проверенная QEMU-регрессией), `hw+fix` (по умолчанию).

> **Найдено симулятором:** с таймингами `hw` лидер пингует по одному участнику раз в 150 мс, а участник считается
> потерянным через `T_MEMBER_LOST = 400 мс`. При ≥ 4 последователях (3×2, 4×4…) участники выпадают и стек бесконечно
> переобнаруживается. `hw+fix` = период опроса `min(150, T_MEMBER_LOST / (2·N))` — предлагаемое исправление для stack.c.

**Платы** — mono_electronics v12, v11b, v10 (из истории git). **Панели** — full, flat 32×32, lattice, 20×20, garland_breakout.
Слои F/In1/In2/B, колесо — зум, правая кнопка — сдвиг. Наведение на контакт/дорожку/переходное подсвечивает всю цепь на всех
слоях, справа — имя цепи, длина по слоям, ширины, переходные, список контактов. Клик — закрепить. Клик по контакту
J_ROW1/J_COL1 — трассировка через FFC (тип B или A) до контакта J_ROW/J_COL панели, её цепи и светодиодов; «Показать на панели».
Поиск — по имени цепи или позиционному обозначению (Enter).

**Куб** — N слоёв (2…32) по 32×32: вращающиеся фигуры, 3D-волна, дождь, сфера, 3D-текст, 2D-демо прошивки по слоям (срезы
со сдвигом времени) или выдавливанием. Мышь — вращение, колесо — зум. Яркость/гамма — та же 8-битная цепочка прошивки.

Кнопка `EN` — английский интерфейс (запуск `LED_Simulator.exe --en`).

## Сборка вручную

Linux: `./build_linux.sh && python3 run_sim.py` (нужны pygame, numpy). Тесты: `python3 tests/test_stack.py [hw|sim|hw+fix]`,
скриншоты: `python3 tests/shots.py out_dir`. Windows: см. workflow (gcc → led_host.dll, PyInstaller --onefile).
